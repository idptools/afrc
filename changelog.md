## Changelog

* **0.5.0** (unreleased):
  * **New features:**
    * **3D ensembles:** `AnalyticalFRC.sample_conformations(n, seed)` generates explicit 3D conformations, one bead per residue, and `AnalyticalFRC.save_ensemble(filename, n, seed)` writes them as a PDB/XTC pair (the PDB holds the topology and the first conformation, the XTC every conformation) that loads directly into mdtraj or SOURSOP. Because every AFRC inter-residue distance is Gaussian, the AFRC defines a Gaussian chain whose bead coordinates are jointly Gaussian with covariance `-J D J / 6` (with `D` the matrix of mean-squared inter-residue distances and `J` the centring matrix), so conformations are drawn from it exactly: every inter-residue distance in the ensemble follows the AFRC's distribution, for all pairs at once. The covariance is factored once per sequence (0.06 s at 1000 residues) and conformations are then drawn in batches with a single matrix product: 5000 conformations take under 0.1 s for a 154-residue sequence and about 2 s for 1000 residues. Analysing a generated ensemble with SOURSOP reproduces the AFRC's Rg and inter-residue distances within sampling error. Adjacent beads follow the AFRC's own neighbour distance distribution (mean ~5.8 A) rather than a fixed 3.8 A spacing, and can overlap, since the AFRC is an ideal chain; the first-to-last bead distance is the `(0, N-1)` inter-residue distance; and the ensemble's Rg is within ~2% of the AFRC's separately calibrated value.
    * New module `afrc/ensemble.py` with the reusable pieces: `gaussian_chain_factor()` and `sample_gaussian_chain()` (which work for any Gaussian chain), and `write_pdb()`, `write_xtc()` and `write_ensemble()` for one-bead-per-residue coordinates. The PDB writer has no dependencies (CA beads named from the sequence, `CONECT` records so viewers draw the chain, long remarks wrapped at 80 columns); the XTC writer uses mdtraj, imported only when needed, and `write_ensemble()` checks everything before writing so a failure never leaves half a pair behind. The module is fully type-hinted.
    * New optional dependency group: `pip install "afrc[ensemble]"` installs mdtraj for writing XTC files.
    * **`afrc-ensemble` command-line tool** (installed with the package): `afrc-ensemble -s <sequence> -n <conformations> -m afrc -o <prefix>` generates an AFRC ensemble and writes `<prefix>.pdb`, `<prefix>.xtc` and `<prefix>_report.txt`; `--pdb-only` writes a single multi-model PDB instead (no mdtraj needed), and `--seed` makes a run reproducible. Without `--seed` a fresh seed is drawn and recorded in the report, so any run can be repeated exactly. Everything that can be checked up front (the sequence, the output directory, mdtraj for XTC output, the PDB 9999-model limit) is checked before the ensemble is generated, so a bad run fails with a clear message, exit status 1, and no files. `-m` selects the model (see the next entry).
    * **Ensemble report:** the command prints (and saves) a report checking that the ensemble is model-like. New module `afrc/ensemble_report.py` provides it as `compare_ensemble_to_gaussian_model()`, which returns an `EnsembleReport`. Each check compares a quantity measured in the ensemble, with a standard error estimated from the ensemble itself, against the model's exact expectation: the root-mean-square Rg, the mean first-to-last bead distance, the Kirkwood-Riseman Rh, the mean-squared and mean inter-residue distances in bands of sequence separation, and Kolmogorov-Smirnov tests of three representative distance distributions against the exact Maxwell distribution. The banded checks reduce each conformation to one number per band, so their standard errors account for all the correlations between residue pairs. Checks fail beyond 5 standard errors (or a KS p-value below 1e-5); across ~2000 simulated correct ensembles the largest deviation seen was 4.0 standard errors, and for a 50-residue chain a 2% error in the chain's size is always flagged with 1000 conformations and a 1% error with 5000. Ensembles from the wrong sequence, with shuffled beads, or with fixed 3.8 A bonds are all flagged. The report also gives context that is not expected to match exactly (the AFRC's separately calibrated Rg, the whole-chain Re, bead spacing and the apparent scaling exponent), and marks ensembles of fewer than 100 conformations as not assessed.
    * `write_multimodel_pdb()` in `afrc/ensemble.py` writes an ensemble as a single multi-model PDB (one `MODEL`/`ENDMDL` block per conformation, `CONECT` records once), and `AnalyticalFRC.save_ensemble()` gains a matching `pdb_only` argument. Every model's `ATOM` block differs only in its coordinates, so the writer builds the block once with the coordinates as format fields and fills it in with a single `%` operation per model, writing one model at a time; this gives exactly the same text as formatting each line but is ~4x faster (0.8 s rather than 3.5 s for 400 residues x 5000 conformations) and never holds the whole file in memory.
    * `AnalyticalFRC.get_mean_squared_distance_map()` returns the model's mean-squared distance for every pair of residues. Because every AFRC inter-residue distance is Gaussian, this matrix fully specifies the pairwise statistics; unlike `get_distance_map()` it is computed for every pair at once from running sums, without building the inter-residue matrix.
    * The new modules (`ensemble.py`, `ensemble_report.py`, `cli.py`) are fully type-hinted and pass `mypy --strict`, and `AnalyticalFRC.__init__()`, `get_mean_radius_of_gyration()` and `get_mean_end_to_end_distance()` now carry type hints too.
    * **Ensembles for every model.** `FreelyJointedChain`, `FreelyRotatingChain`, `WormLikeChain`, `WormLikeChain2`, `SAW` and `NuDepSAW` gain the same four methods as the AFRC: `sample_conformations()`, `save_ensemble()` (PDB/XTC pair or `pdb_only`), `check_ensemble()` (which returns the report) and `get_mean_squared_distance_map()`, and `afrc-ensemble -m` accepts `fjc`, `frc`, `wlc`, `wlc2`, `saw` and `saw-nu`, with `--segment-length`, `--c-inf`, `--lp`, `--prefactor` and `--nu` for the model parameters (a parameter given for a model that does not use it is a usage error). How each is generated:
      * **Freely jointed and freely rotating chains - exact.** Bonds of exactly `b`, in independent random directions (FJC) or at a fixed bond angle with uniformly random torsions (FRC). The ensembles are the chains themselves, so their mean-squared distances are exact for every pair (`k b^2` for the FJC, the finite-k freely rotating chain result for the FRC); note that `c_inf = 1` is a fixed 90 degree bond angle, which has the FJC's size but is a different chain.
      * **Worm-like chain - exact up to a controlled discretization.** Each residue is split into straight sub-segments, each drawn from a von Mises-Fisher distribution about the previous one, and only the bead at the end of each residue is kept. The mean cosine between successive sub-segments is either the worm-like chain's own tangent correlation, `exp(-s/Lp)`, or `(2 Lp - s)/(2 Lp + s)`, which makes the discretized chain's long-range size grow at exactly the continuous chain's rate and leaves only a short-range error of `s^2/2`; `worm_like_chain_discretization()` picks whichever needs fewer sub-segments to match the exact continuous worm-like chain's mean-squared distances to within 0.02% at every separation. Stiff chains use the former (12 sub-segments per residue at `lp = 50 A`) and flexible ones the latter (47 at `lp = 3 A`, 221 at `lp = 0.1 A` - where the worm-like chain's own correlation would need 807). The inner loop is plain elementwise arithmetic with random numbers drawn a block of sub-segments at a time, so 500 conformations of a 134-residue chain take ~1 s at `lp = 0.1 A` rather than ~12 s. The report checks against the discretized chain's exact values and states the difference from the continuous chain. `WormLikeChain` and `WormLikeChain2` generate identical ensembles - the Zhou and O'Brien expressions are both approximations to the same chain - and differ only in which analytical P(r) the report compares against.
      * **SAW and nu-dependent SAW - a Gaussian approximation.** Coordinates are drawn exactly from the Gaussian chain with the model's mean-squared distances, `(prefactor |i - j|^nu)^2` (fractional Brownian motion, valid for any `0 < nu < 1`), so the size and scaling of every distance are right, but the distributions are Gaussian rather than des Cloizeaux, there is no excluded volume, and the radius of gyration comes out ~5% below the universal-ratio value. Genuine self-avoiding conformations would need an explicit simulation. The report says all of this.
    * **The report is now model-general.** `compare_ensemble_to_model()` takes a `ModelExpectations` (the exact mean-squared distance matrix plus whatever else the model fixes). Every model is checked on the root-mean-square Rg, the first-to-last distance and the banded mean-squared distances; Gaussian models (the AFRC) keep the mean-distance, Kirkwood-Riseman and Kolmogorov-Smirnov checks; and models with rigid geometry get exact structural checks - bond length (FJC, FRC), bond angle (FRC) and finite extensibility (FJC, FRC, WLC) - which are assessed for any number of conformations. Context rows compare the ensemble with the model's own Rg and whole-chain Re and with its analytical end-to-end distribution (the Kuhn-Grün, Gaussian, Zhou, O'Brien or des Cloizeaux form, for the N-1 residues between the end beads), and model-specific notes are printed. Quantities fixed by a model's geometry fluctuate only at the level of floating-point rounding, so their standard error is floored at 1e-9 relative - without this a rounding-level difference produced z-scores of 10-70 for correct freely rotating chains. Re-calibrated on 2560 simulated correct ensembles of the new models (2-50 residues, 100-1000 conformations): none was flagged and the largest deviation was 4.0 standard errors. A 0.3% error in the FJC bond length, a change in `c_inf` from 2.0 to 2.05, a 3% error in the persistence length and a 2% error in the SAW prefactor are all caught with 1000 conformations. `compare_ensemble_to_gaussian_model()` remains as a wrapper, and `AnalyticalFRC` gains `check_ensemble()` too.
    * Shared helpers in `afrc/ensemble.py`: the generators `sample_freely_jointed_chain()`, `sample_freely_rotating_chain()` and `sample_worm_like_chain()`; the exact mean-squared distances `freely_rotating_chain_msd()`, `worm_like_chain_msd()` and `discrete_worm_like_chain_msd()` with `worm_like_chain_discretization()` and `mean_squared_distance_map()`; and `save_conformations()`, `validate_sequence()` and `validate_n_conformations()`, used by every model's `save_ensemble()` and `sample_conformations()`. Gaussian-chain samples are now explicitly centred (for small scaling exponents rounding could otherwise leave a ~1e-8 A offset), and zero-residue chains give zero beads. The model constructors now carry type hints.

* **0.4.3** (unreleased):
  * **Behavior-changing scientific fixes:**
    * **Zhou worm-like chain (`WormLikeChain`):** the end-to-end distribution assigned real probability to distances *beyond the contour length*, which is physically impossible. The Zhou (2004) expression is a series expansion in `Lp/Lc` and `r/Lc` and is simply not meaningful for `r > Lc`, but for short and/or stiff chains it returns substantial positive values there - around 30% of the weight for a 2-residue chain at the default `lp = 3 A`, and over half for a 5-residue chain at `lp = 10 A`. That region is now explicitly zeroed. Chains of more than ~20 residues at the default persistence length are unaffected (the change is below 1e-6 relative), and the distribution reproduces the exact worm-like chain `<R^2> = 2*Lp*Lc - 2*Lp^2*(1 - exp(-Lc/Lp))` to machine precision for long chains; short chains now return smaller (and physical) values. A chain whose contour length is comparable to or shorter than the persistence length has no valid region at all and previously produced a NaN-filled distribution; it now raises a `WLCException`.
    * **Zhou worm-like chain grid:** the `r` grid was fixed at `21*sqrt(N)`, which is comfortably wide for `lp = 3 A` but cut into the tail of `P(r)` for stiffer chains (it reached only 2.4 times the size scale at `lp = 10 A`). The grid now always extends to at least four times the ideal-chain size scale `sqrt(2*Lp*Lc)`.
    * **Kirkwood-Riseman hydrodynamic radius:** `get_mean_hydrodynamic_radius('kirkwood-riseman')` computed `1/<r_ij>` - the inverse of the *mean* inter-residue distance, taken from the distance map - whereas the Kirkwood-Riseman equation requires the mean of the *inverse* distance, `<1/r_ij>`. For a Gaussian chain the two differ by exactly `4/pi`, so the returned Rh was systematically 27% too large (and `Rg/Rh` came out near 1.05 rather than the ~1.3-1.5 expected for an ideal chain). Each inter-residue `PolymerObject` now exposes `get_mean_inverse_end_to_end_distance()`, which returns the exact closed form `<1/r> = sqrt(6/(pi <r^2>))` for the Gaussian distribution, and the hydrodynamic radius is `1/<1/r_ij>` averaged over every residue pair. This is the same form of the equation used by Nygaard et al. (2017), Pesce et al. (2023) and SOURSOP's `mode='kr'`. For the 154-residue test sequence Rh drops from 29.35 A to 23.00 A. The `'nygaard'` mode is unchanged. A single-residue chain now raises an `AFRCException` in either mode rather than returning a divide-by-zero (the Nygaard denominator `N^0.6 - N^0.33` is zero at `N = 1`, which previously returned `-0.0` with a NumPy warning).
    * **PRE profiles (`get_pre_profile()`):** the `W_H` argument is the proton Larmor frequency entering the Solomon-Bloembergen spectral-density term `3*tau_c/(1 + W_H^2*tau_c^2)`, which requires the *angular* frequency `omega_H = 2*pi*nu_H` (rad/s). The docstring described it as the linear frequency in Hz and the default was `600000000`, which makes the dispersive term a factor of `(2*pi)^2 ~ 39.5` too small and over-estimates the relaxation rate `gamma` by ~11% at the default `tau_c = 4 ns` (the effect on the intensity-ratio profile is smaller, ~5% in the transition region). The default is now `2*pi*600e6` (~3.77e9 rad/s, i.e. still a 600 MHz magnet) and the docstring says so explicitly. This brings the function into line with SOURSOP's `SSPRE` class, which the docstring cites and which adopted the same convention in 2.0.3. Anyone passing `W_H` explicitly as a linear frequency should multiply it by `2*pi`.
    * **Contact fractions (`get_contact_fraction()` / `get_contact_map()`):** the fraction was evaluated with the trapezoid rule over the binned probability mass function and then divided by the grid spacing. Because the trapezoid rule halves the two end bins, this systematically under-counted by half the weight of the last bin below the threshold - a ~1.5% relative error at a 5 A threshold on the default 0.05 A grid, 0.7% at 10 A, and proportionally worse on the coarser grid used with `adaptable_P_res=True`. The fraction is now the cumulative weight of the bins below the threshold (i.e. the discrete CDF of the distribution actually returned by `get_interresidue_distance_distribution()`), which tracks the analytical Gaussian-chain CDF to within the grid discretisation. All contact fractions increase very slightly as a result.
    * **O'Brien worm-like chain (`WormLikeChain2`) for long chains:** the normalization constant `C1` contains `exp(3*Lc/(4*Lp))`, which overflows once that exponent passes ~709 - about 500 residues at `lp = 2 A` and 750 at the default `lp = 3 A` - and the distribution then came back entirely NaN (as did every mean derived from it). The distribution is now evaluated in log space and normalized numerically, so it never touches `C1`, and works for any chain length (checked to 5000 residues). `C1` itself is still computed (now in log space) for reference.
    * **O'Brien worm-like chain grid:** the `r` grid scaled with `lp` but not with `aa_size`, and was capped at `35*sqrt(N)`, so it cut into the tail of `P(r)` for large segment sizes or stiff, long chains - the RMS end-to-end distance came out ~3% low at `aa_size = 10 A` and ~2% low at `lp = 50 A`, `N = 1000`. The grid now always reaches four times the ideal-chain size `sqrt(2*Lp*Lc)` (and never passes the contour length). The model now matches the exact worm-like chain `<R^2>` to within 0.2% in all of these regimes. For typical parameters the old grid also clipped a little of the tail - most at `lp = 4 A`, where mean and RMS values were up to 0.06% low for chains of a few hundred residues - so these now rise very slightly; at `lp = 3 A` the change is below 5e-5.
    * **Freely jointed chain grid:** the `r` grid was fixed at `21*sqrt(N)`, which is fine for the default `b = 3.8 A` but truncated the distribution for larger segment (Kuhn) lengths - the RMS end-to-end distance was just under 1% low at `b = 10 A` and over 25% low at `b = 20 A`, even though the docs suggest Kuhn lengths of 7-10 A. The grid now always reaches four times `b*sqrt(N)` (capped at the contour length). The default `b = 3.8 A` is unaffected.

  * **Bug fixes (code):**
    * `AnalyticalFRC('')` (an empty sequence) was accepted by the constructor; most quantities then silently came out as zero and the Nygaard hydrodynamic radius as NaN. It now raises an `AFRCException`. (Zero-length `PolymerObject`s are still used internally for the diagonal of the inter-residue matrix - that is unaffected.)
    * `get_contact_fraction()` raised a bare `IndexError` when the threshold was smaller than one grid step (e.g. `threshold = 0.03` at the default 0.05 A resolution), because it tried to take a grid spacing from a single-element slice. That code path no longer exists (see the estimator fix above) and such thresholds simply return 0.0. It also validates its residue indices before the `R1 == R2` short-circuit, so an invalid pair such as `(-1, -1)` raises an `AFRCException` instead of returning 1.0.
    * `get_pre_profile()` now routes `label_position` through the shared residue-index validator, so a non-integer label (e.g. a string) raises an `AFRCException` rather than a `TypeError`.
    * `SAW` and `NuDepSAW` accepted a zero or negative `prefactor` and silently returned an all-NaN distribution; they now raise `SAWException` / `NuDepSAWException`.
    * `get_contact_fraction()` (and so `get_contact_map()`) raised a bare `TypeError` from inside NumPy for a non-numeric threshold; it now raises an `AFRCException`.
    * `get_mean_interresidue_radius_of_gyration()` built the whole [n x n] inter-residue matrix before checking for `R1 == R2`; it now returns 0.0 for that case straight away, like the other inter-residue methods.
    * `pyproject.toml` declared `numpy>=1.12.0`, but the package uses `np.nan_to_num(..., nan=, posinf=, neginf=)` (NumPy 1.17+) and requires Python 3.10, for which the oldest NumPy is 1.21. The floor is now `numpy>=1.21`.
    * Removed the unused `zero_length` branch in `WormLikeChain2` (an empty sequence always fails the contour-length check first), and made the unreachable fall-through in `get_mean_hydrodynamic_radius()` an explicit `else`.

  * **Performance:** none of these change any result - every public `AnalyticalFRC` output was checked to be bitwise identical before and after, across sequences, both grid resolutions and seeded sampling.
    * **Memory in the contact map and distribution-mode distance map:** every entry of the [n x n] inter-residue matrix cached its full `P(r)` grid, so `get_contact_map()` or `get_distance_map('distribution')` left all of them allocated - 6.8 GB at 400 residues, growing roughly as N^2.5 (so a 1000-residue sequence would need ~70 GB). Matrix entries no longer cache their distributions (`PolymerObject` gains a `cache_distributions` argument, default True, which `AnalyticalFRC` turns off for the matrix); recomputing one takes tens of microseconds. At 400 residues the peak memory of these calls drops from 6.8 GB to a few MB, and the first call is also a little faster (4.4 s to 3.1 s). The trade-off is that a *repeated* contact map on the same object is no longer served from cache (0.5 s previously, now the same 3.1 s as the first call). The full-chain distributions are still cached.
    * **Single-pair queries no longer build the whole matrix:** `get_interresidue_distance_distribution()`, `get_mean_interresidue_distance()`, `get_mean_interresidue_radius_of_gyration()`, `sample_inter_residue_distance_distribution()`, `get_contact_fraction()` and `get_pre_profile()` used to build all n^2/2 sub-chains in order to use one pair (or one row). They now build just the segment(s) they need, unless the matrix already exists. A single `get_mean_interresidue_distance()` call on a 1000-residue sequence goes from 11.4 s to ~20 microseconds, and a 400-residue PRE profile from 1.6 s to 0.3 s. Methods that visit every pair (distance and contact maps, internal scaling, Kirkwood-Riseman Rh) still build the matrix once and keep it.
    * **Faster matrix construction:** each sub-chain counted every residue type four times over (once per prefactor) - 6.4 million `str.count` calls at 400 residues. It now counts each residue type once and skips absent ones; the loop order is unchanged, so the prefactors are bitwise identical. Building the matrix at 400 residues goes from 1.4 s to 0.4 s.
    * Replaced the per-element Python loops (`np.vectorize` and explicit loops) in `PolymerObject` and both worm-like chain models with vectorized NumPy. For `PolymerObject` the results are bitwise identical, but distribution-mode distance maps are ~60x faster (28 s to 0.5 s for a 154-residue sequence).

* **0.4.1** (July 2026):
  * **Behavior-changing scientific fixes:**
    * **O'Brien worm-like chain (`WormLikeChain2`):** fixed a sign error in the closed-form radius of gyration. The `1/(4*C2^2)` term (which is `-Lp^2` in the Benoit-Doty form) was being added rather than subtracted, so `get_mean_radius_of_gyration()` over-estimated Rg - by ~5% for a 50-residue chain, and badly for short chains, where it left a spurious constant offset instead of the correct rigid-rod limit of `Lc^2/12`. The corrected expression now reproduces Benoit-Doty exactly and respects the rigid-rod bound (`Rg^2 <= Lc^2/12`) at every chain length.
    * **nu-dependent SAW (`NuDepSAW`):** fixed the `A1` and `A2` normalization prefactors. The gamma functions were being evaluated at `5 + g/delta` and `3 + g/delta` instead of `(5+g)/delta` and `(3+g)/delta`, and in `A1` the `(3+g)/2` and `(5+g)/2` terms were applied as multipliers rather than exponents. Because `A2` sets the width of the distribution, this meant the root-mean-square end-to-end distance did not match the requested size scale - by 33% at `nu = 0.4`, 12% at `nu = 0.5` and -5% at `nu = 0.598`. The unexplained factor of `pi` in the size scale (flagged in a source comment as a suspected symptom of an error elsewhere) was compensating for this and has been removed. With the corrected prefactors `sqrt(<Re^2>) = prefactor * N^nu` holds exactly for any `nu`, and setting `nu = 0.598` now reproduces the fixed-exponent `SAW` model. The corrected constants agree with those hard-coded in `saw.py`, which were derived independently.
    * **Mean Rg via the scaling law:** `get_mean_radius_of_gyration('scaling law')` returned `<Re>/sqrt(6)`. That ideal-chain relation holds between *root-mean-square* radii, so applying it to the mean end-to-end distance under-estimated `<Rg>` by ~5% and left the `'scaling law'` and `'distribution'` modes disagreeing. It now uses the calibrated composition-weighted `RG_R0` prefactor (which was already in `config.py` but unused, and is back-calculated from the same Lhuillier fits that generate the distribution). The two modes now agree to better than 0.05%. This also affects `get_mean_interresidue_radius_of_gyration()`, which defaults to `'scaling law'`.
    * **Self-avoiding walk (`SAW`) radius of gyration:** the universal `<Rg^2>/<Re^2>` ratio was evaluated with a hard-coded `nu = 0.589` while the model's end-to-end distance scales as `N^0.598`, so the Rg and Re returned by the same object described chains with different scaling exponents. Both now read a single `self.nu = 0.598` attribute (alongside `self.gamma`), set once in the constructor, so the two cannot drift apart again. `get_mean_radius_of_gyration()` returns values 0.65% smaller than before (`Rg/sqrt(<Re^2>)` goes from 0.4008 to 0.3982), and now agrees with `NuDepSAW` evaluated at `nu = 0.598` to seven significant figures. Note that `theta = 0.3` and `delta = 2.5` are deliberately left as they are: together with `a = 3.67853` and `b = 1.23152` they form the matched set of constants tabulated by O'Brien et al., and are only a rounded description of the same exponent.
    * **SAW / SAW-nu distribution grid:** the `r` grid was fixed at `21*sqrt(N)` while these models' size scale grows as `N^nu` with `nu > 0.5`, so for long chains the grid cut into the tail of `P(r)` and biased the mean and RMS low (by 0.5% at N = 1000 and 1.8% at N = 3000). The grid now always extends to at least four times the model's own size scale.
    * **`WormLikeChain2` short-chain check:** the constructor compared the number of residues against the persistence length, mixing a residue count with a length in Angstroms. It now compares the contour length (`N * aa_size`) with the persistence length, as the error message always claimed.

  * **Bug fixes (code):**
    * `sample_inter_residue_distance_distribution()` did not validate its residue indices. Out-of-range indices raised a bare `IndexError`, and - worse - negative indices silently wrapped around and sampled the wrong pair of residues. Both now raise an `AFRCException`. The redundant index-swapping logic was removed (the inter-residue matrix is symmetric).
